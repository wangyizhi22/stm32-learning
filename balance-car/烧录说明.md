# bal_hal 编译 & 烧录说明

这个工程是把原来的标准外设库(StdPeriph)版本 `bal/` 改写成 HAL 库版本，
并且已经配好了 EIDE + J-Link 的构建和烧录流程。

---

## 一、先接线（最关键的一步）

### 1. SWD 四根线接到平衡车上

STM32F103C8T6 用 SWD 方式下载，只需要这几根线：

| 平衡车板上 | J-Link 20 针接口 | 说明 |
|---|---|---|
| **PA13** (SWDIO) | **Pin 7** (TMS) | 数据线，必须接 |
| **PA14** (SWCLK) | **Pin 9** (TCK) | 时钟线，必须接 |
| **GND** | Pin 4 / 6 / 8 / 10（任意一个） | 共地，必须接 |
| **3.3V** | **Pin 1** (VTref) | 让 J-Link 知道目标电压，**必须接** |
| NRST（复位脚） | Pin 15 (nRESET) | 可选，但建议接，能解决大部分"连不上"问题 |

> 板子上如果没有现成的排针，通常有 4 个标着 `SWDIO` `SWCLK` `GND` `3V3` 的焊盘
> （或者标 `DIO` `CLK`）。可以对照 `平衡车电路图.pdf` 找。
>
> J-Link 的 20 针接口上，**Pin 1 在哪里**看接头上的小三角/缺口标记，别插反了。

### 2. 给平衡车通电

J-Link **不会**给板子供电（Pin 1 是电压检测输入，不是电源输出）。
平衡车必须**自己用电池供电**，或者用 USB 线给 C8T6 核心板供电。

**如果板子没电，J-Link 就会一直卡在 `Connect...` 不动。**

### 3. ⚠️ 安全提醒

烧录前**把平衡车的轮子架空**（车抬起来，别放地上），
因为程序一烧进去就立刻开始跑，电机会转。

## 二、在 VSCode 里编译

1. 用 VSCode 打开这个文件（不是打开文件夹）：
   `bal_hal/bal_hal.code-workspace`
2. 确保装了 **EIDE** 扩展（`cl.eide`）
3. 左下角状态栏应该显示 `Debug` / `GCC` / `JLink`
4. 点状态栏的 **✓ (Build)**，或者按 `Cmd+Shift+B` 选 `build`

编译成功后终端会打印内存占用，大致是这样：

```
   text    data     bss     dec     hex   filename
  44164     480    3720   48364    bcec   build/Debug/bal_hal.elf
```

也就是 **Flash 用了约 43.6 KB / 64 KB**，RAM 约 4 KB / 20 KB，余量充足。

## 三、烧录

### 方法 1：EIDE 一键烧录（推荐）

接线、编译都搞定后，点状态栏的 **⬇ (Upload)** 图标，
或者 `Cmd+Shift+P` → 输入 `eide: Upload to Device`。

### 方法 2：命令行用 J-Link Commander

如果 EIDE 抽风，直接命令行烧最稳（把路径换成你自己的）：

```bash
cd "/Users/macbook/Desktop/wyz/C8T6引脚分布等57项文件/bal_hal"

cat > /tmp/flash.jlink <<'EOF'
Device STM32F103C8
Speed 4000
Connect
Erase
LoadFile build/Debug/bal_hal.hex
r
g
Exit
EOF

/usr/local/bin/JLinkExe -NoGui 1 -CommanderScript /tmp/flash.jlink
```

指令含义：`Erase` 全片擦除 → `LoadFile` 烧 hex → `r` 复位 → `g` 运行。

## 四、连不上的时候怎么办

### 实测诊断（2026-10-15，你当前的状态）

在你这台机器上实测的结果：

```
VTref=3.295V                                    ← 板子有电，Pin1/GND 接对了 ✓
Connecting to target via SWD
Error: Failed to initialize DAP.                ← SWDIO/SWCLK 没通到 CPU ✗
Can not attach to CPU. Trying connect under reset.
WARNING: RESET (pin 15) high, but should be low  ← NRST 没接
```

把速度从 4000 → 1000 → 200 kHz 全试了一遍，结果完全一样，
**说明不是信号质量问题，是 SWDIO/SWCLK 这两根线没接好。**

### 按这个顺序查

1. **SWDIO / SWCLK 到底接上没有、有没有接反？**（最可能的原因）
   - PA13 (SWDIO) → J-Link **Pin 7**
   - PA14 (SWCLK) → J-Link **Pin 9**
   - 这两根接反了也连不上，对调一下试试。

2. **J-Link 的 20 针接头，Pin 1 在哪边？**
   接头外壳上有一个**小三角 / 缺口**标记的那一端就是 Pin 1。
   奇数针（1,3,5…19）在一排，偶数针（2,4…20）在另一排：

   ```
    Pin1 VTref      Pin2 NC/5V
    Pin3 nTRST      Pin4 GND
    Pin5 TDI        Pin6 GND
    Pin7 TMS/SWDIO  Pin8 GND      ← PA13 接到这里
    Pin9 TCK/SWCLK  Pin10 GND     ← PA14 接到这里
    Pin11 RTCK      Pin12 GND
    Pin13 TDO/SWO   Pin14 GND
    Pin15 nRESET    Pin16 GND     ← 建议接上
    Pin17 NC        Pin18 GND
    Pin19 5V       Pin20 GND
   ```

3. **把 NRST 接上（Pin 15 → 板子的 NRST / 复位脚）。**
   现在这条告警说明 NRST 悬空。接上之后，即使板子里已经烧了
   占用 PA13/PA14 的旧固件，J-Link 也能"复位下连接"（connect under reset）强行接管。
   连上 NRST 后可以用这个脚本：

   ```
   si SWD
   Device STM32F103C8
   Speed 1000
   Connect
   Exit
   ```
   （J-Link 会自动尝试 connect under reset）

4. **板子的 SWD 焊盘/排针确认一下。**
   平衡车底板或 C8T6 核心板上，找标着 `SWDIO`/`SWCLK`（或 `DIO`/`CLK`）的
   4 个针脚/焊盘，对照 `平衡车电路图.pdf` 确认。杜邦线接触不良也很常见，
   换几根线、或者直接焊上去试试。

5. **确认 GND 真的共地。** 用万用表蜂鸣档量一下 J-Link 的 GND 和板子的 GND 是否导通。

6. **芯片被读保护了。** 连上之后执行：
   ```
   si SWD
   Device STM32F103C8
   Connect
   Unlock
   Exit
   ```
   （`Unlock` 会清空 Flash，原厂固件就没了——不过 `固件.hex` 就在旁边，可以随时烧回去）

## 五、烧完之后

固件跑起来后，第一次上电需要做一次**校准**（MPU6050 的零偏、编码器占空比），
否则姿态解算会有偏差。

校准函数是 `App_Calibrator_DoCalibration()`（在 `User/Src/app_calibrator.c`），
**默认没有被 `main()` 调用**（和原标准库版本一样）。要做校准时，
在 `Core/Src/main.c` 的 `MX_*_Init()` 之后加一行：

```c
App_Calibrator_DoCalibration();   // 校准完会死循环闪灯，之后删掉这行重新烧
```

校准流程：LED 闪 5 秒（把车放平）→ LED 常亮 → 电机自动转 10 秒（**轮子要架空**）
→ 校准 MPU6050 10 秒 → 保存到 Flash → LED 持续闪烁。
看到持续闪烁就说明校准完成，把这一行删掉重新烧一次即可。

## 六、工程结构

```
bal_hal/
├── Core/
│   ├── Src/main.c              ← 外设初始化(MX_xxx_Init) + 主循环
│   │   stm32f1xx_hal_msp.c     ← 引脚/时钟/中断/DMA 配置
│   │   stm32f1xx_it.c          ← SysTick / ADC / DMA 中断
│   ├── Inc/main.h
│   └── Startup/startup_stm32f103xb.s
├── Drivers/                    ← STM32F1 HAL 库 + CMSIS（官方原版）
├── MyLib/                      ← delay / button / si2c / usart / pid / lpf / qmath
├── User/                       ← 平衡车业务代码（从 bal/ 移植过来）
├── Test/                       ← 测试函数（用 My_USART_Printf 打印调试信息）
├── .eide/eide.yml              ← EIDE 工程配置（编译选项、J-Link 烧录参数）
└── STM32F103C8TX_FLASH.ld      ← 链接脚本（64K Flash / 20K RAM）
```

### 标准库 → HAL 的主要对照

| 原来 (StdPeriph) | 现在 (HAL) |
|---|---|
| `RCC_APB2PeriphClockCmd()` + `GPIO_Init()` | `MX_GPIO_Init()` / `HAL_xxx_MspInit()` |
| `EXTI_Init()` + `NVIC_Init()` | `MX_GPIO_Init()` 里配 EXTI 模式 + NVIC |
| `TIM_Cmd()` / `TIM_CtrlPWMOutputs()` | `HAL_TIM_PWM_Start()` |
| `TIM_SetCompare1()` | `__HAL_TIM_SET_COMPARE()` |
| `USART_Init()` / 裸 RXNE 中断 | `MX_USART3_UART_Init()` + `HAL_UART_Receive_IT()` |
| `FLASH_Unlock()` / `FLASH_ProgramHalfWord()` | `HAL_FLASH_Unlock()` / `HAL_FLASH_Program()` |
| `DMA_Init()` / `DMA_Cmd()` | `HAL_DMA_Start()` |

**注意**：编码器的 EXTI 触发方式必须是**双边沿**（`GPIO_MODE_IT_RISING_FALLING`），
T 法测速靠 A 相上升沿和下降沿之间的时间差算速度，少一个边沿速度就算错了。
